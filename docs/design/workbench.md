# Cage 工作台

Cage 面向在本机项目中编码的用户。主界面管理本地项目、网页、终端和文件编辑器；设置页集中管理环境配置。界面采用 Codex 桌面端的侧栏与内容区结构，保留 Cage 的名称和图标，不提供账户或云端协作入口。

## 主界面

Cage 只使用一个持久环境，VM、账户登录态、开发工具和家目录在所有项目间共享。项目对应实际共享的文件夹，左侧项目列表直接读取控制服务保存的目录，包含默认工作区；每个目录下只列出在该目录创建的终端。目录旁的加号直接新建终端，折叠目录不影响其中的进程。

浏览器是独立的应用入口，网页使用内容区顶部的横向标签栏，不归属于项目。点击左侧“浏览器”返回仍在运行的浏览页面，顶部加号与 ⌘T 新建网页。文件编辑器页也在顶部标签栏显示，并在标题中标明打开的目录；打开项目与切换终端均不关闭已有网页。终端内容区显示所属目录及终端名称。

```text
┌──────────────────┬──────────────────────────────────────┐
│ Cage             │ 网页 A × │ 网页 B × │ 文件 · A × │ + │
│ 工作台           ├──────────────────────────────────────┤
│ 浏览器           │ ←  →  ↻  地址栏                      │
│ 打开项目         ├──────────────────────────────────────┤
│ 项目文件         │                                      │
│                  │                                      │
│ 项目           + │             当前工作内容             │
│ ▾ 项目 A       + │                                      │
│     终端 1       │                                      │
│ ▾ 项目 B       + │                                      │
│     终端 2       │                                      │
│                  │                                      │
│ 运行状态         ├──────────────────────────────────────┤
│ 设置             │ 网络状态                    停止环境 │
└──────────────────┴──────────────────────────────────────┘
```

未启动时，主界面提供“启动 Cage 环境”，无需选择项目。每份配置只创建和使用一个持久 VM；默认工作区通常为 `~/.claude-cage-workspace`。环境就绪后可直接使用浏览器和终端，再按需打开本地文件夹。重新打开应用继续连接同一环境。

打开项目时，主机通过已有受目录约束的 SFTP 实现，把用户选定的文件夹动态挂载到当前 VM：macOS 使用同名路径，Windows 的 `C:\Users\name\project` 映射为 `/c/Users/name/project`。项目 A 切换到 B 后，A 的共享目录、终端进程、浏览器和编辑器页保持运行。目录旁的加号始终在对应目录新建终端；终端工具栏在该终端所属目录创建新会话，项目文件入口使用当前选择的目录。明确打开的目录继续保留，并在环境重启时恢复共享。所有项目处于同一环境，可以访问其中已共享的目录、工具和账号。

VM 身份固定保存在主机私有的 `environment.json`；最后打开的项目保存在 `workbench.json`，明确打开的目录保存于 `projects.json`。控制服务通过 `/api/status` 的 `projects` 返回完整目录列表，不设最近使用条数限制。终端与编辑器创建请求可携带 `workspace`，只接受默认目录、当前目录及已保存的项目目录；省略时沿用最后打开的项目。前端的目录选择不修改共享授权，也不影响浏览器。首次升级优先保留原有环境的虚拟磁盘；历史其他 VM 不自动删除。项目切换不改变环境身份，也不触发代理探测、网络重检或环境重启。网络与系统配置的修改继续按既有流程验证并重启。

标签支持重命名、置顶、拖动排序和关闭。浏览器标签通过右键或 Shift+F10 打开操作菜单，终端通过行末菜单管理。重命名只改变显示名称；置顶标签排列在各自列表前方，拖动调整同一列表内部的顺序。名称、置顶与顺序保存在本地。⌘1–9 与 ⌘⇧[ / ] 按当前列表的显示顺序切换：浏览器中切换顶部网页，终端中切换同目录的终端。关闭当前网页后激活相邻浏览器页。刷新后重新连接仍存活的终端与浏览器，已结束的进程不因标签恢复而重新启动。

浏览器标签栏与新建按钮垂直居中，标签总宽度随内容区调整，不显示横向滚动条。空间充足时标签最大宽度为 220px；拥挤时当前标签优先保留标题空间，其他标签平分剩余宽度。极窄标签保留可点击位置和悬停标题，右侧搜索入口可按名称或网址查找所有页面。指针拖动时标签跟随移动，相邻标签实时让位；松手保存顺序，Esc 或指针取消恢复原顺序。置顶和普通标签分别在各自分组内排序。

地址栏右侧星标与 ⌘D 打开当前网页的收藏编辑框，收藏夹按钮与 ⌘⇧O 打开收藏面板。收藏支持名称、HTTP(S) 地址、单层收藏夹分组、搜索、移动和删除；删除收藏夹将其中的收藏移至未分类。打开收藏通过现有浏览器新建页接口进入 VM，不在主机执行收藏网址。文件编辑器与内部浏览器页面不提供收藏。

收藏由主机控制服务保存在当前配置目录的私有 `favorites.json`，Unix 权限为 `0600`，Windows 使用仅当前用户与 SYSTEM 可访问的显式 DACL；所有项目共用，应用和控制服务重启后保留，不与 Chromium 或外部浏览器同步。`GET /api/favorites` 返回 `items` 与 `folders`；`POST /api/favorites` 通过 `save`、`delete`、`save_folder`、`delete_folder` 操作单条记录，沿用工作台认证与来源校验。修改在专用互斥锁下读取最新文件并原子写入，避免并发新增覆盖其他窗口的收藏。保存失败保留编辑输入，读取失败不覆盖原文件。收藏操作不更改 VM、网络或共享目录状态。

## 设置页

设置占据完整窗口，左侧分类为通用、外观、网络与代理、IP 变化规则、时区与语言、环境与恢复；右侧显示表单，底部固定保存区。离开未保存的表单需要确认，保存失败保留输入。返回工作台保留选中的标签与终端，并恢复可见浏览器画面的连接。

通用页提供浏览器默认网站，缺省为 `https://www.bing.com/`。该偏好保存在 `workbench.json` 的 `browser_home_url`，只接受不含认证信息的 HTTP(S) 网址；保存同步至客机浏览器，无需重启 VM 或终端。工作台新建网页、浏览器最后一页关闭后的补充页使用这个地址；连接时将恢复的空白页和 Chromium 内置新标签页转到该地址，已有普通网页继续保留。

网络表单区分已配置值与真实探测结果。代理密码保持遮蔽，留空表示保留；探测结果提供 IP、位置和检测时间。自动时区和语言设置说明来源与应用时机。项目选择放在主界面，环境与恢复页只展示共享目录和配置恢复操作。

网络与代理页提供[内置代理](managed-proxy.md)的节点、订阅、连接和诊断入口，节点管理器是唯一出口来源，DNS 单独配置并经当前节点转发。节点切换撤销旧连接和检测授权，保留终端进程；更换本地端口需要重启环境。公网 UDP、IPv6、ICMP 持续阻断。

## 视觉与交互

外观以可独立配置的浅色、深色主题组织，支持跟随系统切换。主题包含强调色、背景、文字、对比度、界面及代码字体和侧栏透明度。可选的元素颜色覆盖用于侧栏、工具栏、文字层级、输入、边框、按钮、交互与状态；终端另有背景、前景、光标、选区及完整 ANSI 颜色覆盖。未覆盖的颜色继续由基础色和对比度推导，恢复自动颜色即删除对应覆盖。字号在界面层统一缩放。标准侧栏宽 248px，较窄窗口使用 224px；设置正文最大宽度 720px。原生窗口与终端跟随当前主题，VM 内的编辑器及网页保留自身外观。

外观由控制服务独立保存至 appearance.json，前端自动提交，修改失败保留输入并允许重试。读取、保存和本机 Codex 导入分别通过 GET /api/appearance、POST /api/appearance、GET /api/appearance/codex 完成，沿用工作台认证。外观操作不走环境配置应用流程，不重启 VM 或终端；本机导入只复制当前偏好，不创建持续文件监听。

自定义主题库与当前外观一同保存于 appearance.json，最多 50 项。每项具有独立标识、名称及浅深两套主题快照；应用主题只替换两套主题，保留模式、字号和交互偏好。修改当前配色不会自动改写已命名主题，用户需明确选择更新或另存。删除主题仅移除快照。Codex 同步保留此主题库。

主题文件契约为 `{format: "cage-theme", version: 1, name, lightTheme, darkTheme}`。每套主题包含 `preset/accent/surface/ink/contrast/opaqueWindows/fonts`，以及可选的 `colors` 和 `terminal` 颜色表。前端在导入前严格校验版本、字段、字体、六位 HEX 颜色与 256 KB 文件上限；后端对当前主题及全部快照再次校验，未知颜色键、无效颜色、重复标识或超限主题库均不得替换已保存文件。外观保存请求上限为 512 KB。

macOS 的 `importTheme/exportTheme` 原生操作仅接受受信任工作台主框架调用，通过系统文件窗口读写 UTF-8 JSON。Windows 桥接执行相同操作；浏览器使用文件输入与 Blob 下载。取消文件窗口不改动外观，导入同名主题分配新标识，导出内容只含主题配置。原生标题栏跟随当前侧栏颜色，已有终端直接更新 xterm 主题而不重连。

按钮按下即时反馈，项目列表在 180ms 内展开，设置页在 160ms 内进入；减少动态效果模式下直接显示最终状态。工作台终端保持连接。浏览器画面不可见时关闭显示连接，重新可见时重连；浏览器进程、页面、下载和登录状态继续保留。原生窗口隐藏、最小化或关闭也会暂停显示连接，单纯失去键盘焦点不触发暂停。

主要验证视口为 1280×850 与原生最小窗口的内容区 820×558。更窄页面可收起侧栏；设置表单独立滚动，保存操作持续可见。环境连接正常且外网放行仍有效时，品牌区、工作台和状态栏显示绿色带对钩盾牌，并提供状态文字。连接中断、检查中、网络关闭或放行过期时撤销绿色标记；VM 运行但浏览器连接未就绪时显示恢复入口。

界面保留实际网络状态、项目路径和失败原因，日志与详细检查按需打开。

底部状态栏显示当前代理节点到 `www.gstatic.com/generate_204` 的 HTTP 延迟，单位为毫秒。环境运行且没有配置任务时立即检测，之后每 30 秒更新；点击延迟可重新检测。节点或配置版本变化后丢弃旧读数，停止或控制连接中断时显示“延迟 —”，检测失败显示“延迟不可用”。测速沿用内置核心的节点检测接口，不启动代理、不改变节点和外网放行状态；延迟成功不代表环境已获准联网。

## 模块职责

Windows 原生窗口使用 WinForms 与 WebView2，macOS 使用 Swift 与 WKWebView；两者消费同一 `cage desktop --json` 入口和原生桥协议。Windows 使用 QEMU/WHPX 与 Windows ConPTY，Mac 使用 Apple 虚拟化与 POSIX PTY，客机软件及代理出口约束共用。Windows 构建与平台边界见 [Windows 指南](../windows.md)。

主机控制服务管理配置、VM 生命周期、会话与只通向该配置唯一 VM 的连接。前端只调用这个服务。终端在 VM 的 SSH 会话中执行；浏览器控制器和 Chromium 在 VM 内运行。编辑器页面也通过 VM 浏览器呈现，避免将来自 guest 的任意网页脚本作为主机控制页面加载。

应用窗口仅加载本机工作台。外部地址统一交给 VM 浏览器；所有网页与编码进程的网络仍由现有 VM 外代理出口接管。

Chromium 通过继承的私有调试管道接受标签与导航命令，不开放 CDP 端口。网页由用户手工操作，启动时关闭 Blink 的 `AutomationControlled` 标记，避免仅因工作台控制管道而向网页报告自动化模式。浏览器服务停止时，先由控制器通知 Chromium 保存标签和配置后退出，再清理剩余子进程。此设置保留浏览器控制与登录态，不保证第三方网站的人机验证一定通过。

## 验收重点

1. 从应用启动到可操作，无需查终端找端口或复制访问密码。
2. 多网页/多终端切换时状态保持，关闭和恢复行为可预期。
3. 网络和系统设置清晰区分草稿、验证结果及已应用值；失败保留输入和原配置。
4. 代理断线时真实请求失败，控制台仍可操作并支持重试；IP 自动时区只使用代理出口位置。
5. 只将默认工作区和明确打开的项目文件共享给 VM；控制会话、主机代理凭据和主机 API 不向 guest 网页开放。
6. 在 1440×900、较窄窗口及放大文字时检查标签、表单与主要操作的可读性。

## 连接与状态约定

日常入口免密。App 持有主机私有启动密钥，通过 localhost 换取有效期 60 秒的一次性入口，再建立 HttpOnly 会话；浏览器和编辑器的内部凭据由工作台管理。链接消费后从地址栏移除，不能重复使用。直接打开一个未认证的控制地址会要求从 App 或启动器进入，不提供人工密码表单。

虚拟显示由 Xtigervnc 提供，直接监听仅限 guest 私有 Unix socket；X0tigervnc 负责已验证的剪贴板与显示传输。轻量窗口管理器让 kiosk Chromium 随显示区域调整，不提供桌面壳。工作台通过浏览器控制器调整显示模式，以 2 倍像素呈现；画面连接断开时按有上限的间隔重试，不因此重启 VM 或终端。

自动时区查询通过已选代理完成。应用配置前验证，随后停止环境、保存前一份配置并重启；探测失败保留原配置。运行中不会因定期位置探测自动重启。用户选择恢复配置时，同样明确提示终端中断，并启动恢复后的环境。按键偏好单独保存，不重启环境。

共享下载先存入 guest 私有目录，完成后以编码用户权限统一写入 Cage 环境默认工作区的 Downloads。同名文件不覆盖，路径与符号链接受到检查。终端通过专用 SSH 连接进入 guest，禁用本机转义、本机命令、代理转发及宿主环境继承。工作台刷新可以连接仍在运行的会话；控制服务或 VM 重启后的旧终端不能复原。

下载列表区分下载中、保存中、已保存、失败和已取消。只有完整文件在共享目录中发布后才显示已保存；写入失败保留客机源文件，可在修复空间或共享连接后重试。状态原子保存在浏览器私有目录，控制器恢复后只对已完整下载且源文件仍在的项目提供保存重试；下载被中断时需要从原网页重新下载。列表保留最近 50 条结束记录，最多同时处理 50 个未结束下载，保存过程串行执行。成功保存后清理对应客机源文件；清理失败显示提示，已保存文件保持可用。

编辑器由独立系统服务监督，进程异常退出时自动重新启动。工作台的编辑器恢复操作只重启该服务并重新加载项目页面，保留 VM、浏览器和工作台终端。迁移旧版编辑器时，先核对用户、安装目录、Cage 私有配置和监听参数；无法确认身份的进程不自动停止。

## 更新与后台接管

左下角更新入口在发现新版时显示向下箭头，悬浮提示“下载更新”。点击后通过所选受管代理下载 Release 安装包并核验摘要、应用身份及平台签名：macOS 检查同一 Developer ID Team 与 Apple 验证结果；Windows 检查 Authenticode 信任链、相同发布者公钥和安装器版本，随后安装并重启；代理失败无直连回退。有运行环境时，原生确认框要求用户先保存并停止。安装或新工作台启动失败时尝试恢复旧 App，无法恢复时保留备份和失败信息。ad-hoc 或未签名开发构建不进入自动安装流程。

更新源为公开 GitHub Releases 接口，不需要 GitHub 凭据，也不读取浏览器登录会话。访问失败时显示原因；草稿、附件缺失或非公开发行物不能作为可用更新。首次安装使用对应平台的 DMG 或 Windows EXE 安装器，后续版本由应用内更新器检查和下载。

应用启动通过私有启动密钥核对正在运行的控制服务。身份包含完整版本、当前可执行文件的 SHA-256 和控制协议号；文件摘要在进程启动时固定，同版本号的不同构建也能区分。相同构建复用后台；不同构建只有在没有运行环境、作业和存活终端时才自动接管。接管期间拒绝新任务，停止独立代理并优雅退出控制服务，然后由新程序取得同一配置的控制锁。

已有工作时，原生窗口显示“更新待完成”，可明确打开现有环境保存文件，也可在保存后选择停止环境并完成更新。连接旧后台时，窗口标题和关于窗口持续标明更新未完成，不能只用新 App 的版本号代表全部运行组件。

不支持版本握手的旧控制服务需要一次明确的停止与迁移操作。启动器使用认证会话提交停止，确认同一任务成功、环境停止和终端关闭，再核对进程所属用户、可执行文件、完整启动参数、工作目录、监听端口和启动时间后发送退出信号。身份变化、停止失败或退出超时都会中止更新，不发送强制杀死信号。此兼容操作仅支持 macOS，普通启动不会执行。

安装器共用 `cage prepare-update --json`：空闲后台退出后返回 `prepared`，仍需保存停止时返回 `stop_required`；用户确认后调用 `prepare-update --stop --json` 完成停止与退出。失败以非零退出码和 `error` 状态返回。该入口不启动新后台；安装器替换应用并重新打开后，由常规启动入口接管。

## 持久环境的组件与工具版本

应用与 Linux 磁盘分别升级。Cage 的浏览器控制器、显示服务、编辑器服务和下载辅助程序以嵌入资源的统一摘要标识；只有完整启动脚本成功后，才向客机写入 root 所有的组件清单。工作台连接时读取该清单，缺失、协议不兼容或摘要不符都会显示需要更新，不能仅因健康检查成功就把旧组件标为就绪。

“更新环境组件”在现有 VM 中重新应用幂等脚本，重启浏览器与编辑器相关服务，保留磁盘、项目、账户和工作台独立终端。操作前需要保存浏览器和编辑器中的修改；编辑器内的集成终端可能结束。脚本失败时清单保持无效，用户可查看任务结果并重试。已有运行依赖完整时，组件更新可在暂停外网时执行；用户的暂停状态继续保留。

“更新环境工具”是单独的显式操作，需要组件已经同步且外网处于有效放行状态。Chromium 使用 Debian 软件源的更新，code-server、mise 和 Claude 使用随 App 固定的最低版本；当前版本更高时保留现有版本。初次安装与后续升级共用固定安装器，下载包核验摘要后才安装。工具更新不重建磁盘，完成后重新启动相关服务并核对组件状态。更新期间继续运行原有网络检查与短期续租；人工暂停、停止或配置变化仍会阻止联网。

`GET /api/environment/versions` 只在用户查看环境设置时读取工具版本，不加入周期状态查询。返回控制服务实际构建、组件的 `current` / `required`、后端判定的 `update_required`、工具实际与最低版本，以及 `tools_update_allowed`。组件与工具更新分别通过 `POST /api/environment/update`、`POST /api/environment/tools` 提交到现有作业队列。应用原生版本来自 App 的版本信息，不能用旧控制服务的版本代替。
